# 8. 에이전트 운영하기: 신원, 추적, 보정

**[English](08-operating-agents.md) | 한국어** · [과정 지도](README.ko.md) · 실습: [승인 게이트 보정하기](../../ma_pmo/learn/labs/lab6_calibration/README.ko.md)

## 목표

다른 사람이 의존하는 에이전트 시스템을 운영합니다. *누가* 무엇을 했는지, 실행이 *왜* 그렇게
동작했는지, 안전 게이트가 위험한 출력을 실제로 걸러 내는지 알 수 있어야 합니다.

## 개념

2~4강에서 통제 장치를 만들었습니다. 그것을 운영하려면 세 가지가 더 필요합니다.

1. **신원.** 승인 기록은 누가 승인했는지 말해야 감사 기록이 됩니다. 그리고 그 이름은 요청 본문에
   아무나 써 넣을 수 있으면 안 됩니다. 인증이 "승인자: alice"를 주장이 아닌 사실로 만듭니다.
2. **추적.** 화요일에 품질이 떨어지면, 로그는 무언가 *있었다*는 것만 알려 줍니다. 트레이스는 실행을
   워크플로 → 에이전트 → LLM 호출의 나무로 보여 주고, 실패와 대체 경로를 정확한 단계에 표시합니다.
   로그에만 남는 대체 경로는 늦게 발견됩니다.
3. **보정.** 확신도 기준값은 확신도가 정답률을 따라갈 때만 위험을 거릅니다. ECE와 Brier로 측정하고,
   에이전트가 말하는 확신도 값이 몇 종류인지 보고, 기준값은 감이 아니라 *검토 건수 대 빠져나간 오류*
   표로 고르세요.

## MA-PMO에서는

- **신원** — `ma_pmo/api/auth.py`: `MA_PMO_AUTH_MODE=api_key|custom`, 역할 `viewer`, `operator`,
  `approver`, `admin`. 인증이 켜져 있으면 결정에 기록되는 승인자는 인증된 사용자입니다. 인증이 꺼져
  있는 동안 대시보드 상단 바가 경고합니다. 안내: [docs/AUTH.ko.md](../AUTH.ko.md)
- **추적** — `ma_pmo/core/tracing.py`: `OTEL_ENABLED=true`면 시나리오 실행이 `invoke_workflow` →
  `invoke_agent` → `chat` span이 됩니다. 실패한 LLM 호출은 오류로, 대체 경로는
  `ma_pmo.fallback=true`로 표시됩니다. Jaeger 실행: [infra/otel](../../infra/otel/README.md)
- **보정** — `ma_pmo/eval/calibration.py`: A4 리스크 경보 대 레이블, 처리된 승인. 판정은 보정됨 /
  과신 / 과소 확신 / *변별력 없음* / 데이터 부족이고, 기준값 표가 함께 나옵니다. `ma-pmo eval`,
  보고서, 평가 화면에서 볼 수 있습니다.

## 해보기

```bash
OTEL_ENABLED=true ma-pmo harness a7_ablation 2> spans.txt    # span은 stderr로
grep -c '"ma_pmo.fallback": true' spans.txt                  # 이번 실행의 대체 경로 수

curl -X POST localhost:8000/scenarios/risk_escalation/run   # 확신도가 붙은 A4 경보
ma-pmo eval | sed -n '/\[calibration\]/,$p'
```

## 흔한 실수

- **입구에서만 인증.** 프록시가 인증은 하지만 누구나 넣을 수 있는 "사용자" 헤더를 서명 없이 넘긴다면
  신원이 아닙니다. API가 그 프록시를 통해서만 접근 가능할 때만 전달된 헤더를 신뢰하세요.
- **트레이스에 프롬프트 기록.** 프롬프트에는 개인정보나 기밀이 들어갈 수 있습니다. MA-PMO의 span에는
  id, 모델, 토큰 수, 대체 경로만 담고 본문은 담지 않습니다.
- **상수 확신도.** 항상 0.85를 말하는 결정론적 에이전트는 평균적으로는 보정돼 보여도 좋은 경보와 나쁜
  경보를 가르지 못합니다. ECE만 보지 말고 *확신도 값 종류*를 함께 보고하세요.
- **승인 데이터로만 조정.** 승인·반려는 게이트에 걸린 메시지에만 생기므로 확신도가 낮은 쪽으로 치우친
  표본입니다. 라벨이 있는 표본도 따로 유지하세요.

1. 팀이 일주일에 제안 10건을 검토할 수 있습니다. 기준값 표에 0.8 → 검토 9건 / 빠져나간 오류 3건,
   0.9 → 검토 14건 / 0건으로 나옵니다. 어떻게 하겠습니까?
2. "오전 9시부터 LLM이 죽어 있었다"를 잡으려면 어떤 span 속성으로 경보를 걸겠습니까?
