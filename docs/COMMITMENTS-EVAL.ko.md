# 약속 평가

**[English](COMMITMENTS-EVAL.md) | 한국어**

결정이 만든 의무([REVIEW.ko.md](REVIEW.ko.md#약속commitment))가 지켜지지 않으면 알아차리고, 지켜지면 그대로 두는지
확인합니다. 다음 명령으로 다시 돌릴 수 있습니다.

```bash
ma-pmo eval --commitments
```

## 기준(첫 실행 전에 정함)

평가를 돌리기 전에 적어서 커밋했습니다. 약속과 질문이 제대로 동작한다고 보려면 모두 충족해야 하고, 모두 0이어야 하는
개수입니다.

| 기준 | 세는 것 | 목표 |
|---|---|---:|
| 놓쳤는데 아무도 모름 | 기한까지 지키지 않았는데 `violated`가 되지 않았거나, 채무자에게 알리지 않은(보고 단계도, 기록된 알림도 없는) 약속 | 0 |
| 지켰는데 미이행 처리 | 제때 지켰는데 `violated`가 된 약속 | 0 |
| 놓쳤는데 보고되지 않음 | 놓쳤는데 두 단계 시간 안에 책임자까지 보고되지 않은 약속 | 0 |
| 놓쳤는데 결정 재검토 안 됨 | 놓친 게이트 조건이나 승인 조건 중, 세 단계 시간이 지나도 결정이 승인 큐로 돌아가지 않은 것 | 0 |
| 불필요한 질문 | 있는 사실에 대해 한 질문 | 0 |
| 표시 없는 기본값 | 답이 없어 기본값을 쓰고도 결과에 확인 안 됨 표시가 없는 경우 | 0 |

목표 없이 함께 보고하는 것: 사람에게 늘어난 일(실행당 질문과 보고 메시지 수), 생성부터 해결까지 걸린 시간.

## 사례

- **조건.** 데모 포트폴리오를 그 달력(2026-02-16 기준)으로 돌리면 PROJ-14와 PROJ-31이 G3를 조건부(차단 태스크)로
  통과합니다. 사람이 각 게이트를 승인하면서 조건을 하나씩 붙입니다. 그래서 게이트마다 두 가지 약속이 생깁니다.
  게이트 조건은 차단 태스크의 선행 작업이 끝나면 트래커가 이행 처리하고, 승인 조건은 사람이 근거와 함께 이행 처리합니다.
  기한은 3일, 7일, 14일입니다.
- **질문.** PROJ-22에 시작일이 없어 A2가 묻습니다. 답 기한은 1일, 3일, 5일입니다. 대조 실행은 시작일을 그대로 두므로
  질문이 나오면 안 됩니다.
- **이해관계자.** 사례마다 사람이나 트래커가 *제때*(기한 전날), *늦게*(기한 이틀 뒤), *없음*(끝내 하지 않음)으로
  움직입니다. 하루씩 날짜를 넘기며, 그날 할 일이 있으면 하고, 트래커를 확인하고, 기한 점검을 돌립니다.

모든 사례는 임시 워크스페이스에서 LLM 없이 결정론적 경로로 돕니다.
